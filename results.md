# Results

Machine: Intel(R) Xeon(R) Processor (8 vCPU VM), 15 GB RAM, Python 3.13.5, SQLite 3.46.1, sqlite-vec v0.1.9, fastembed with `sentence-transformers/all-MiniLM-L6-v2` (384-dim, CPU). Page size 4096.

Raw numbers: `results.json`, `results_extra.json`, `embed_stats.json`. This file is generated by `report.py`.

## Dataset

- 10,000 synthetic memories from 18 templates, 50 users, average 69.3 characters, 4,358 unique texts (near-duplicates are intentional).
- 300 paraphrased queries, one per sampled memory, generated by the same script.

## Recall latency and hit@5, k=5

Query embedding is **not** included (1.4 ms median in this run).

| method | queries | median | p95 | hit@5, global (all 10k) |
|---|---|---|---|---|
| FTS5 (bm25, OR of non-stopword terms) | 300 | 0.41 ms | 1.32 ms | 9.3% |
| sqlite-vec vec0 KNN (float32) | 300 | 4.34 ms | 4.72 ms | 27.7% |
| hybrid: FTS5 top-50 + vec0 top-50, RRF | 300 | 5.50 ms | 6.26 ms | 18.0% |
| BLOB column, read all + numpy cosine | 50 | 14.34 ms | 18.35 ms | 24.0% |
| JSON-text vectors, read all + decode + cosine | 10 | 1,201 ms | 1,224 ms | 10.0% |
| vec0 `bit[384]` top-50 + float rerank | 300 | 0.76 ms | — | 27.7% |

Global hit@5 is low because each target sits among hundreds of near-identical template siblings. Use it to compare methods, not as a quality score.

### Filtering after top-k

- Global top 5, then drop other users' rows: 0.25 of 5 results left on average; 77.3% of queries return nothing.
- Filter before k (vec0 `user_id text partition key`): 5/5 results, 0.62 ms median.
